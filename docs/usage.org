This page starts where installation stops.  It first gets one backend playing,
then explains the interface and the keys; the reference tables live in
[[file:configuration.org][Configuration]] and the protocol is in
[[file:backends.org][Backends]].  If something does not answer, jump to
[[file:troubleshooting.org][Troubleshooting]].

There is no wrong way to begin.  You can use the player with the keyboard,
the mouse or ~M-x~, and you cannot break a file by looking around.  If a word
is unfamiliar, [[file:glossary.org][Words and ideas]] is written for exactly that moment.

* Choose where your music lives
:PROPERTIES:
:CUSTOM_ID: choose-a-backend
:END:

A backend is the part of orpheus that reaches your music.  Choose the one that
matches what you already have; you can switch later with ~B~ without
restarting Emacs.

| Your music is… | Choose | What it needs |
|----------------+--------+---------------|
| in a Music Player Daemon library | ~mpd~ | a running MPD and its socket or address |
| a folder or links on this computer | ~local~ | ~mpv~ on ~exec-path~ |
| on another computer, with no daemon there | ~ssh~ | ~ssh~, and ~sftp~ when the shell cannot run ~cat~ |

If you already run MPD, ~mpd~ is usually the least surprising choice: the
daemon keeps the library and the queue, and orpheus is the window onto it.
If you have a folder of files and no daemon, start with ~local~.  If the music
is on a server, ~ssh~ copies one track at a time and plays it here.

Every section below is self-contained; read the one that matches your choice
and skip the others for now.

* Quick start
:PROPERTIES:
:CUSTOM_ID: getting-started
:END:

#+begin_src emacs-lisp
(require 'orpheus)

;; A daemon on this machine, reached over its socket.
(setq orpheus-backend 'mpd)
(setq orpheus-mpd-socket "~/.mpd/socket")
(orpheus)
#+end_src

For MPD over the network, leave the socket nil and set the host and port:

#+begin_src emacs-lisp
(setq orpheus-mpd-host "music.example.org")
(setq orpheus-mpd-port 6600)
#+end_src

The password goes nowhere near this repository, and it does not need to go in
your init either.  ~orpheus-mpd-password~ nil means "read ~MPD_PASSWORD~",
then "ask ~auth-source~", and ~auth-source~ reads =~/.authinfo.gpg= by
default, so GPG can hold the secret and gpg-agent asks for its passphrase once
per session.

The entry is found by ~machine~ and ~port~, and those two words are
~orpheus-mpd-host~ and ~orpheus-mpd-port~ — ~localhost~ and ~6600~ unless you
changed them.  That holds for a socket connection too: the socket says where to
connect, the host and port say which entry belongs to it.  So a daemon on
another machine needs

#+begin_src emacs-lisp
(setq orpheus-mpd-host "music.example.org")
(setq orpheus-mpd-port 6600)
#+end_src

and an entry that spells the same host and port:

#+begin_src shell
machine music.example.org port 6600 password ...
#+end_src

Written from the values your init sets, with the secret read without echo:

#+begin_src shell
host=music.example.org port=6600      # what orpheus-mpd-host and -port say
read -r -s -p "MPD password for $host:$port: " secret && echo
umask 077
printf 'machine %s port %s password %s\n' "$host" "$port" "$secret" |
  gpg --batch --yes --quiet --encrypt --default-recipient-self \
    > ~/.authinfo.gpg
unset secret
#+end_src

~--default-recipient-self~ seals it for your own key; ~--recipient
you@example.org~ seals it for another one.  ~--batch --yes~ lets the same
recipe run a second time without stopping at a prompt.

Read it back, and read the line rather than the exit status: an entry that
stops at ~password~, or one written for a host the daemon no longer has, is not
a password, and MPD then refuses every command it is given.

#+begin_src shell
gpg --quiet --decrypt ~/.authinfo.gpg
#+end_src

A password that is found is sent, so keep the store to the daemons it
describes.  A daemon with no password answers ~ACK ... incorrect password~ to
one it never asked for, and the session then fails to log in instead of
starting without it.

A ~pass~ store works instead, once Emacs is told about it.  Its secret is asked
for only when a connection needs it, and the password leaves the connection
once MPD has it.

#+begin_src emacs-lisp
(require 'auth-source-pass)
(auth-source-pass-enable)
#+end_src

For a session rather than an installation the environment is enough, though
every process of your user can read it.  ~MPD_PASSWORD~ wins over
~auth-source~, so it overrides the store:

#+begin_src shell
export MPD_PASSWORD='...'
#+end_src

The local backend needs no daemon at all:

#+begin_src emacs-lisp
(setq orpheus-backend 'local)
(setq orpheus-local-directory "~/Music")
(orpheus)                                  ; then 2 for the files tab, RET to play
#+end_src

or, from anywhere:

#+begin_src emacs-lisp
(orpheus-play-file "~/Music/album/01.flac")
(orpheus-play-url "https://www.youtube.com/watch?v=...")
#+end_src

Music on another machine is copied over ssh and played by mpv here:

#+begin_src emacs-lisp
(setq orpheus-backend 'ssh)
(setq orpheus-ssh-host "music.example.org")   ; or "me@music.example.org"
(setq orpheus-ssh-directory "Music")          ; nil starts in the login home
(orpheus)
#+end_src

There is no daemon on the far side: ~ls -1p~ fills the files tab, a remote
~find~ fills Search, falling back to a recursive ~ls~ when the host has no
~find~, and RET starts a transfer.  Bytes go straight to a private
cache file as they arrive, so another download never freezes Emacs; the
Downloads tab shows what is queued and what is moving, and ~d~ cancels a row.
When the remote shell rejects ~cat~, the transfer uses ~sftp~ instead;
~orpheus-ssh-sftp-program~ names the program (which must be installed here),
and ~orpheus-ssh-sftp-extra-args~ carries its options, such as ~-P 2222~.  A
one-time check when the backend connects reports which remote commands and
shell features work, and ~M-x orpheus-ssh-diagnose~ shows the same table on
demand.  Playback begins once the copy is complete, so a large track spends its
transfer time downloading rather than playing.  While the current track plays, the next
~orpheus-ssh-prefetch~ queue entries are fetched in the background, and completed
tracks stay on disk, so replaying one or moving to the next needs no second
transfer.  A play request always goes ahead of a prefetch.  The cache lives in
~orpheus-ssh-cache-directory~, by default ~orpheus-cache-directory~/ssh, which
is =~/.cache/orpheus/ssh=.  It survives a disconnect and a reboot, and
~orpheus-cache-max-bytes~ deletes the least recently used files once it passes
the limit; ~orpheus-ssh-cache-count~ is an optional stricter limit on the
number of tracks.  Listings, searches and cover lookups share one multiplexed
ssh connection, so a download does not make a directory change wait, and
entering a folder shows ~loading…~ at once rather than the old rows.  Your key
must already let you in, because ssh has no terminal in which to ask for a
passphrase.  A host whose key is not in =~/.ssh/known_hosts= needs one
~ssh music.example.org~ from a terminal first, or
~(setq orpheus-ssh-extra-args '("-o" "StrictHostKeyChecking=accept-new"))~ once.
mpv must be installed here, and the audio comes out of this machine.  The start
directory is relative to the login home or absolute; a leading =~= is not
expanded, because the path is quoted for the remote shell.  The shared socket
lives in a short private directory (~orpheus-ssh-control-directory~); when ssh
cannot use it, the command is retried without multiplexing rather than failing
the tab.  To change backend without restarting Emacs, press ~B~ in the player
or run ~M-x orpheus-switch-backend~; the current backend is disconnected and
the tabs follow the new one.

* Your first five minutes
:PROPERTIES:
:CUSTOM_ID: first-five-minutes
:END:

This is a gentle path, not a test.  Each step is reversible, and you can stop
at any point.

1. Run ~M-x orpheus~.  The player opens in the selected window.  If it says
   “not connected”, the backend has not finished connecting; give it a moment
   and read [[file:troubleshooting.org][Troubleshooting]] if it stays that way.
2. Look at the top of the window.  The header line tells you the backend, what
   is playing and the time.  The tab row below it is a map of the views your
   backend offers.
3. Press ~2~ for the files or Directories tab.  ~RET~ enters a folder or plays
   a track; ~^~ goes back up.  If you chose MPD, start with ~1~ for the Queue
   instead.
4. Press ~SPC~ to pause or resume, ~>~ and ~<~ to change track, and ~s~ to
   stop.  The now-playing card shows the same controls if you prefer the
   mouse.
5. Press ~?~ for the command menu and ~H~ for the full help.  Both explain
   what a command does before you run it.  ~q~ buries the player and leaves
   the music alone.

The worst thing that happens if you press an unfamiliar key is usually a
message in the echo area.  When in doubt, ~H~ is the way back to the map.

** If you are new to Emacs

- ~M-x~ means hold Alt and press x.  If Alt is awkward in a terminal, press
  Escape, release it, then press x.
- ~RET~ is Enter or Return.  ~SPC~ is the space bar.
- ~C-x~ means hold Control and press x; ~S-TAB~ means Shift and Tab.

You do not need to learn Emacs Lisp to use the player.  The code examples are
only for people who want to keep a setting between sessions.

* Getting help
:PROPERTIES:
:CUSTOM_ID: getting-help
:END:

~?~ opens the command menu, ~H~ opens the help buffer, and
~M-x orpheus-tutorial~ starts a guided tour.  The help buffer is the map: it
explains what the tabs, the queue, the equalizer and the backends do, lists
every key, and says where to look when a backend is not answering.  The
tutorial is the shortest path from a fresh install to a playing track, and
each step is a button as well as a key.  [[file:configuration.org][Configuration]] and
[[file:backends.org][Backends]] are the reference for the options and the backend protocol.  For a
quick answer without leaving the player, ~?~ is usually enough; for an
explanation, ~H~.

* Keys
:PROPERTIES:
:CUSTOM_ID: keys
:END:

The keys follow Emacs conventions: ~C-n~ and ~C-p~ move, ~C-v~ and ~M-v~
page, ~C-s~ searches, ~C-x C-s~ saves, and ~q~ buries the player.  ~?~ opens a
transient menu of the commands, and ~H~ lists the same table in a buffer.
If ~C-x~ or ~M-x~ is new notation, [[file:glossary.org#keyboard-words][Keyboard words]] explains it in one
paragraph.  The mouse
follows the same actions: mouse-1 selects a row or tab, mouse-2 plays a row,
and mouse-3 opens the context menu for a row, a tab or a playlist editor row.
The now-playing card is a control panel too: previous, play or pause, next and
stop carry the usual media glyphs, with the repeat, random, single and consume
toggles in their own group; a click on the bar seeks to that point of the
track.

| Key                    | Meaning                                                  |
|------------------------+----------------------------------------------------------|
| ~RET~                  | play the row or portable playlist, or open the album, artist or directory |
| ~n~, ~C-n~, ~j~        | next row                                                 |
| ~p~, ~C-p~, ~k~        | previous row                                             |
| ~C-v~, ~M-v~           | one screen down, one screen up                           |
| ~M-<~, ~M->~           | first row, last row                                      |
| ~TAB~, ~S-TAB~         | next tab, previous tab                                   |
| ~1~ … ~7~              | the tabs, in the order shown; SSH adds Downloads after Queue |
| ~^~, ~C-b~             | back up one level in the tab                             |
| ~m~, ~u~               | mark the row, unmark it                                  |
| ~U~, ~t~               | unmark everything, invert the marks                      |
| ~a~, ~A~               | queue the marked rows (or this one), queue everything here |
| ~e~                    | edit the portable playlist at point (Playlists tab)       |
| ~N~                    | create a new playlist, asking for its directory          |
| ~i~                    | insert the player's tracks in the playlist editor        |
| ~d~, ~C-k~             | delete from the queue, or cancel a download               |
| ~D~                    | clear the queue                                          |
| ~/~, ~C-s~             | search                                                   |
| ~C~                    | jump to the playing row                                  |
| ~SPC~                  | play or pause                                            |
| ~s~                    | stop                                                     |
| ~>~, ~<~               | next track, previous track                               |
| ~f~, ~b~               | seek forward, seek back                                  |
| ~M-<up>~, ~M-<down>~   | volume up, volume down (also ~+~ and ~-~)                |
| ~z~, ~x~, ~c~, ~v~     | repeat, random, consume, single                          |
| ~M-u~, ~M-U~           | update the library, rescan it                            |
| ~C-x C-s~              | save the queue as a portable M3U8 playlist; a new name asks where |
| ~g~                    | refresh the status and the current tab                   |
| ~V~                    | the spectrum visualizer                                  |
| ~M-t~                  | next player colour preset                                |
| ~M-l~                  | next layout preset                                       |
| ~M-c~                  | next visualizer colour ramp                              |
| ~?~                    | the menu: transport, modes, queue, playlists, views      |
| ~H~                    | help: concepts, keys and troubleshooting                 |
| ~E~                    | the equalizer's simple mode: presets, save, delete, set the gains |
| ~M-E~                  | the equalizer's advanced mode: a bar graph of every band |
| ~L~                    | lyrics for the current track, following the playback      |
| ~B~                    | switch to another backend                                |
| ~q~                    | bury the player                                          |
| ~mouse-1~, ~mouse-2~   | select a row, play it                                    |
| ~mouse-1~ on the card  | press a transport button; on the bar, seek to that point |
| ~mouse-3~              | open the row, tab or playlist editor menu                |

On the Downloads tab, RET plays a finished copy, retries a failed transfer, or
waits for one that is still moving; ~d~ cancels the selected transfer.  The
header line counts active and queued transfers and shows their aggregate
throughput while they run.  On the Playlists tab, ~a~ appends a portable
playlist's tracks, ~d~ deletes the portable playlist file, and ~e~ opens its
editor; RET loads it in place of the queue.

Queueing is guarded: ~A~ (and ~a~ with many marks) asks before adding more than
~orpheus-ui-add-confirm-threshold~ rows, and a queue over
~orpheus-ui-queue-warning-size~ says how to clear it.  MPD also refuses a
directory URI, because its ~add~ would expand the whole tree.  Connecting never
queues anything; a queue that is already large was restored by MPD's own
~state_file~, and ~D~ empties it.

The equalizer has two faces, and both reach the same gains.  ~E~ loads a
preset, saves the current curve or reads ten numbers; it works with the local
and ssh backends, and says so on MPD, whose audio leaves through the daemon.
~M-E~ draws the curve as ten bars: up, down, left and right move the selected
band, ~M-<up>~ and ~M-<down>~ move it farther, ~n~ and ~p~ change band, and a
click inside a bar sets the gain of the column clicked.  ~0~ zeroes the band,
~r~ resets every band, ~i~ inverts the curve, ~t~ tilts it, ~e~ turns the
equalizer on or off, and ~P~, ~s~ and ~d~ load, save and delete presets.  A
right click opens the same commands as a menu.

~L~ shows the lyrics of the current track in a side window and marks the line
that is playing, when the words carry times.  RET on a line seeks to it, ~SPC~
plays or pauses, and ~g~ reads them again.  The backend finds the words where
it keeps them, so the window is available on every backend, though a host
without ~cat~ or a track without a sidecar or a tag has none to show.

All of the transport commands are ordinary interactive functions, so any of
them can be bound in ~global-map~ or in a repeat map.

* Graphics, and how it degrades
:PROPERTIES:
:CUSTOM_ID: graphics
:END:

- *In a graphical frame* the cover for the current track, or for the album
  folder being browsed when the track has none, is drawn above the list in a
  box of ~orpheus-ui-art-size~ that keeps its height whether a cover is
  loading, missing or drawn, so the list never moves under it, and a window
  left with too few rows under the cover grows to fit them; an image Emacs
  cannot decode is skipped.  The visualizer is an SVG bar graph with rounded
  bars and a colour ramp, or the block-character graph when Emacs was built
  without SVG.  The ramp comes from the player theme, and ~M-c~ switches to a
  named visualizer ramp (Aurora, Ember, Ice, Spectrum, Mono) and back to your
  own colours; ~orpheus-vis-theme-presets~ adds more, and
  ~orpheus-vis-background~ sets the background behind the SVG bars.
- *In a terminal* no cover is fetched or drawn, and the list, the status line,
  the progress bar and the faces are unchanged.  The visualizer falls back to
  block characters, which is a real rendering, not a placeholder.
- *In either* the status line is text and the progress bar is Unicode by
  default and ASCII with ~orpheus-ui-plain-ascii~.
- *Over SSH* nothing is different from a local terminal, because nothing needs
  a display: ~display-graphic-p~ is the only test that matters.
