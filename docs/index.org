Welcome.  You do not have to read this manual in order, and you do not need to
know anything about music daemons, SSH or Emacs Lisp to start.  The player is
meant to be usable first and configurable later.

If a word feels unfamiliar, keep [[file:glossary.org][Words and ideas]] open beside the page you
are reading.  It explains the vocabulary in plain language, with no assumption
that you have used a music player inside Emacs before.

* A five-minute path

1. Install Emacs 29.1 or newer and the program for the backend you want.  The
   [[file:../README.org#install][install section]] names them.
2. Choose where your music already lives:
   - a Music Player Daemon with a library → ~mpd~;
   - files on this computer → ~local~;
   - files on another computer → ~ssh~.
3. Open the player with ~M-x orpheus~, press ~2~ for the files tab, use ~RET~
   to enter a folder or play a track, and press ~H~ whenever you want the map.

Nothing is queued, moved or deleted merely by opening the player.  Browse
first; the keys that change something say so.

* A reading order

1. Install the package and its backend program from the [[file:../README.org][README]].
2. Follow [[file:usage.org][Using orpheus]] until the first track plays.
3. Read [[file:features.org][Feature tour]] for the parts you have not touched yet.
4. Read [[file:architecture.org][How it works]] when you want to know why it behaves this way.
5. Read the [[file:platforms.org][cross-platform guide]] before changing a
   platform-specific program or path.
6. Keep [[file:configuration.org][Configuration]] and [[file:backends.org][Backends]] nearby when
   you change the setup.
7. Use [[file:troubleshooting.org][Troubleshooting]] instead of guessing when a
   connection stops answering.
8. Read [[file:development.org][Development]] before opening a pull request.

You can also read [[file:glossary.org][Words and ideas]] first if you prefer to know the
vocabulary before the tour.  Both orders work.

* Conventions

- ~C-x~ is a key sequence; ~RET~, ~TAB~ and ~SPC~ are the keys Emacs calls by
  those names.  [[file:glossary.org#keyboard-words][Keyboard words]] spells out the notation.
- Option names are written exactly as the code spells them, so they can be
  passed to ~setq~ or found with ~M-x customize-group~.
- Code blocks are Org source blocks.  The examples are meant to be copied into
  =init.el= and evaluated; the shell blocks are meant to be run as written.
- A terminal frame loses images, not controls.  The visualizer and cover art
  have text fallbacks; the tab row simply omits the logo.

The logo is the orpheus icon from the jointhefreeworld project icon set.  It is
shown in the README and, when the frame can display images, at the start of the
player's header line.
