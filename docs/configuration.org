Every option below lives in the ~orpheus~ customization group, so

#+begin_src emacs-lisp
M-x customize-group RET orpheus RET
#+end_src

shows the same list with widgets and documentation.  The tables are the quick
reference; the examples at the end show the settings that are easiest to get
wrong.  Backend-specific setup, including MPD passwords and SSH keys, is in
[[file:backends.org][Backends]].

You do not need to set any of this to try the player.  The defaults are meant
to be sensible, and the five-minute path in [[file:usage.org][Using orpheus]] works without
a single option.  Come back here when you want to change where a backend looks,
how long it waits or how the player looks.

* How to read this page

- A *default* is what happens if you never mention the option.  ~nil~ usually
  means “use the built-in choice” or “off”; ~t~ means on.  [[file:glossary.org#nil-and-t][Words and ideas]]
  explains both if Emacs Lisp is new.
- Set an option in your init file with ~setq~, or change it for the session
  with ~M-x set-variable~.  ~M-x customize-group RET orpheus RET~ is the
  discoverable form with descriptions and widgets.
- The examples use complete ~setq~ forms.  Copy one, change the paths to
  yours, and evaluate it.  A wrong path usually means an empty tab, not a
  broken player.

Backends are explained in [[file:backends.org][Backends]]; if you only want to know which one to
pick, the [[file:usage.org#choose-a-backend][backend chooser]] is shorter.

* Options
:PROPERTIES:
:CUSTOM_ID: options
:END:

** The session
:PROPERTIES:
:CUSTOM_ID: the-session
:END:

| Option                     | Default | Meaning                                        |
|----------------------------+---------+------------------------------------------------|
| ~orpheus-backend~          | ~mpd~   | ~mpd~, ~local~, or any registered backend      |
| ~orpheus-refresh-interval~ | ~1.0~   | seconds between two status reads               |
| ~orpheus-volume-step~      | ~2~     | volume change of the volume commands           |
| ~orpheus-seek-step~        | ~5~     | seconds of the seek commands                   |
| ~orpheus-notifications~    | ~t~     | notify on track change                         |
| ~orpheus-mode-line-width~  | ~40~    | columns the mode-line track is given           |
| ~orpheus-mode-line-controls~ | ~t~   | show previous, play, next and stop buttons in the mode line |
| ~orpheus-cache-directory~  | ~$XDG_CACHE_HOME/orpheus/~ | downloaded tracks, covers and generated files |
| ~orpheus-cache-max-bytes~  | ~10737418240~ | largest size of the cache, 10 GiB; nil keeps everything |

~orpheus-backend~ chooses the backend when the player starts.  In the player,
~B~ (or ~M-x orpheus-switch-backend~) disconnects the current backend,
connects the chosen one and rebuilds the tabs, so trying another backend does
not need a restart.  The backend is the part that reaches your music; the
interface stays the same.

The cache lives in =~/.cache/orpheus= by default and survives a reboot.
Tracks and covers are deleted, least recently used first, when the directory
grows past ~orpheus-cache-max-bytes~; the track being played is never one of
them.  Deleting the directory is always safe: it is read again.

~orpheus-mode-line-controls~ is on by default.  The mode line then shows
previous, play or pause, next and stop buttons beside the track, each one
click away, and its right-click menu has seeking, the four modes, the
equalizer, lyrics, detach and quit.  Set it to ~nil~ to keep only the status
glyph and the track; the track itself still answers ~mouse-1~, ~mouse-2~ and
~mouse-3~.  ~M-x orpheus-detach~ opens the player in a new graphical frame and
closes its old window; a terminal says a frame needs a display.  The ~⧉ detach~
button after the tabs runs the same command.

| ~orpheus-mpd-host~        | ~"localhost"~ | host, when the socket is nil             |

** The local backend
:PROPERTIES:
:CUSTOM_ID: the-local-backend
:END:

| Option                       | Default     | Meaning                                |
|------------------------------+-------------+----------------------------------------|
| ~orpheus-local-directory~    | ="~/Music"= | where the files tab starts             |
| ~orpheus-local-mpv-program~  | ~"mpv"~     | the player                             |
| ~orpheus-local-audio-driver~ | ~nil~       | what follows ~--ao=~, or nil for the platform |
| ~orpheus-local-extra-args~   | ~nil~       | more mpv arguments, as a list          |
| ~orpheus-local-socket~       | ~nil~       | IPC socket path, or nil for a temporary one; Windows pipes are per Emacs |
| ~orpheus-local-cover-names~  | ~cover.jpg~, ~front.jpg~, … | names tried first next to a track or album folder |
| ~orpheus-local-art-extensions~ | ~jpg~, ~png~, ~webp~, … | extensions accepted as cover art; local and SSH |
| ~orpheus-local-extensions~   | ~mp3~, ~flac~, ~opus~, … | what the files tab shows |

~orpheus-local-audio-driver~ is the escape hatch for a machine that needs a
specific device: ~"pipewire"~, ~"coreaudio/1"~, ~"wasapi"~, ~"alsa/hw:1,0"~.
Left nil, the platform decides (see [[file:backends.org#platforms][Platforms]]).

Any image file can be cover art.  ~orpheus-local-cover-names~ is the order of
preference, so ~cover.jpg~ wins over a stray ~scan.jpg~ in the same folder;
~orpheus-local-art-extensions~ says which extensions count as an image.

~orpheus-local-extensions~ is the list the files tab shows.  Its default
covers the common audio containers (MP3, FLAC, Ogg and Opus, M4A and AAC, WAV,
AIFF, WMA, ALAC, APE, WavPack, DSD, MIDI and more) and the common video ones
(MP4, MKV, WebM, AVI, MOV, MPEG and TS, FLV, WMV, VOB, 3GP and more).  A video
file is listed and played for its sound only: mpv starts with ~--no-video~ and
~--force-window=no~.  MPD ignores this list and uses its daemon's formats.

** The SSH backend
:PROPERTIES:
:CUSTOM_ID: the-ssh-backend
:END:

| Option                          | Default | Meaning                                         |
|---------------------------------+---------+-------------------------------------------------|
| ~orpheus-ssh-host~              | ~nil~   | ~host~ or ~user@host~; nil means not configured |
| ~orpheus-ssh-directory~         | ~nil~   | remote start directory; nil is the login home   |
| ~orpheus-ssh-program~           | ~"ssh"~ | the ssh program                                 |
| ~orpheus-ssh-extra-args~        | ~nil~   | more ssh arguments, as a list                   |
| ~orpheus-ssh-sftp-program~      | ~"sftp"~ | sftp program used when cat is unavailable      |
| ~orpheus-ssh-sftp-extra-args~   | ~nil~   | more sftp arguments, as a list                  |
| ~orpheus-ssh-concurrency~       | ~2~     | simultaneous ssh downloads                      |
| ~orpheus-ssh-prefetch~          | ~2~     | upcoming queue tracks fetched in the background |
| ~orpheus-ssh-split-images~      | ~t~     | fetch a disc track's byte range and cut it here |
| ~orpheus-ssh-command-timeout~   | ~20~    | seconds a listing, search or cover may stay silent |
| ~orpheus-ssh-cache-directory~   | ~nil~   | where downloads are kept; nil is =~/.cache/orpheus/ssh= |
| ~orpheus-ssh-cache-count~       | ~nil~   | completed tracks kept, or nil for only the size limit |
| ~orpheus-ssh-multiplex~         | ~t~     | share one connection; ignored on native Windows |
| ~orpheus-ssh-control-directory~ | ~nil~   | where shared control sockets live; nil picks a short private directory |
| ~orpheus-ssh-control-persist~   | ~600~   | seconds a shared connection stays alive after its last command |

When the host has no ~ffmpeg~, a track of a FLAC image is fetched as the byte
range its seek table names, or estimated from the average bitrate, and cut
here with this computer's ~ffmpeg~ (~ffprobe~ for an estimate).  Set
~orpheus-ssh-split-images~ to ~nil~ to copy such an image once instead; every
track of it then plays from that one cache file.

A control socket is a Unix-domain socket, and its path has a hard platform
limit.  orpheus puts ssh's ~%C~ token in a private directory under
~$XDG_RUNTIME_DIR~ or =/tmp= and measures the expanded name; if no directory
has room it turns multiplexing off and says so.  Set
~orpheus-ssh-control-directory~ to a short private path to choose the
directory, and ~orpheus-ssh-control-persist~ to change how long the shared
connection outlives its last command.  Native Windows OpenSSH has no
~ControlMaster~, so multiplexing is off there.  If ssh still rejects the
socket, the command is retried once without multiplexing.

** Playlists
:PROPERTIES:
:CUSTOM_ID: playlist-configuration
:END:

| Option                       | Default                           | Meaning                                             |
|------------------------------+-----------------------------------+-----------------------------------------------------|
| ~orpheus-playlist-directory~ | ~$XDG_DATA_HOME/orpheus/playlists~ | where portable playlists are read and written       |
| ~orpheus-playlist-new-directory~ | =~/Music= | directory offered for a new playlist              |

The default falls back to =~/.local/share/orpheus/playlists= when
~XDG_DATA_HOME~ is unset.  The directory is made on the first save; an empty
one is a tab with no rows.

** The equalizer
:PROPERTIES:
:CUSTOM_ID: equalizer
:END:

Only the local and SSH backends can apply it: both play through mpv.  The MPD
backend returns nil from ~orpheus-backend-equalizer~, and pressing ~E~ says so,
because its audio leaves through the daemon's output.

There are two ways in.  ~E~ is the simple mode: on or off, a preset, and a
saved preset of your own.  ~M-E~ is the advanced mode: a bar graph of every
band that the arrow keys and the mouse shape, with the band width and the
range beside it.  Both reach the same gains, so a curve made in the editor is
what the menu loads next time.

| Option                          | Default                          | Meaning |
|---------------------------------+----------------------------------+---------|
| ~orpheus-equalizer-enabled~     | ~nil~                            | apply the preset to the backend |
| ~orpheus-equalizer-preset~      | ~"flat"~                         | preset used when none was loaded yet |
| ~orpheus-equalizer-bands~       | 31, 62, … 16000                  | frequencies, in Hz, one gain each |
| ~orpheus-equalizer-max-gain~    | ~12~                             | largest boost or cut, in dB |
| ~orpheus-equalizer-width~       | ~1~                              | width of each band, in octaves |
| ~orpheus-equalizer-gain-step~   | ~1~                              | dB one arrow key moves a band |
| ~orpheus-equalizer-shift-step~  | ~3~                              | dB one shifted arrow key moves a band |
| ~orpheus-equalizer-tilt-step~   | ~3~                              | dB the tilt adds to the lowest band |
| ~orpheus-equalizer-buffer-name~ | ~"*orpheus equalizer*"~          | the editor's buffer |
| ~orpheus-equalizer-preset-file~ | ~$XDG_DATA_HOME/orpheus/equalizer.json~ | saved presets, as JSON |
| ~orpheus-equalizer-state-file~ | ~$XDG_DATA_HOME/orpheus/equalizer-state.json~ | the curve remembered between sessions |
| ~orpheus-equalizer-presets-buffer-name~ | ~*orpheus presets*~ | where the preset manager is drawn |

A preset is one gain in dB for each frequency in ~orpheus-equalizer-bands~.
The built-ins are flat, bass, vocal, treble, loudness, night, podcast, acoustic,
club and v-shape.  Saving a preset writes every user preset to
~orpheus-equalizer-preset-file~, so the file can be copied between machines:

#+begin_src json
{"warm": [0, 0, -1, -2, 0, 1, 2, 3, 2, 1]}
#+end_src

A user preset with a built-in's name replaces it.
~M-x orpheus-equalizer-set-gains~ reads a line of ten numbers for a one-off
shape, and ~M-x orpheus-equalizer-save-preset~ keeps the current gains under a
name.

In the editor, up and down (or left and right) move the selected band by
~orpheus-equalizer-gain-step~, ~M-<up>~ and ~M-<down>~ by
~orpheus-equalizer-shift-step~, and ~n~ and ~p~ change band.  ~0~ zeroes the
band, ~r~ resets every band, ~i~ inverts the curve, ~t~ tilts it, ~e~ turns the
equalizer on or off, and ~P~, ~s~ and ~d~ load, save and delete presets.  A
click inside a bar sets that band to the gain of the column clicked, and a
right click opens the same commands as a menu.  ~M-x
orpheus-equalizer-set-width~ and ~M-x orpheus-equalizer-set-max-gain~ change
the two numbers the filter is built from.

The curve in effect is remembered in ~orpheus-equalizer-state-file~: its
gains, whether the equalizer is on, and the preset's name.  Every backend that
starts, including the one a switch brings in, is given that curve, so the
sound is the same after a restart.  Only the curve and the switch are kept;
the width, the range and the steps stay options in your init.

Presets travel as JSON.  ~M-x orpheus-equalizer-export-preset~ writes one
preset to a file you name, ~M-x orpheus-equalizer-import-preset~ reads a file
holding one preset or many, and ~M-x orpheus-equalizer-copy-preset~ puts one on
the kill ring.  A file holding a bare array of gains takes its own name.  In
the editor, ~x~, ~I~ and ~y~ export, import and copy the same way.

~M-x orpheus-equalizer-preset-manager~ lists the presets you saved, each with
its shape drawn as a sparkline and its gains beside it.  ~RET~ loads the row,
~r~ renames it, ~d~ deletes it after asking, ~y~, ~x~ and ~I~ copy, export and
import, and a right click opens the same menu.  The built-in presets are not
rows: they cannot be renamed or deleted, so the menu on ~E~ lists them.

** Lyrics
:PROPERTIES:
:CUSTOM_ID: lyrics
:END:

~L~ shows the words of the current track in a side window and marks the line
that is playing.  RET on a line seeks to it, SPC plays or pauses, and ~g~ reads
the lyrics again.  Each backend reads them where it keeps them:

- ~local~ reads a ~.lrc~ or ~.txt~ file beside the track, then the lyrics tag
  inside the file (ID3's USLT, Vorbis' LYRICS, MP4's ©lyr) through ~ffprobe~.
- ~ssh~ runs one quoted command on the remote shell for the same sidecar names.
  A host without ~cat~ or compound commands has no lyrics, and says so.
- ~mpd~ reads the sidecar under ~orpheus-mpd-music-directory~ when that names
  the daemon's library on this machine, and otherwise asks the daemon for the
  file's tags with ~readcomments~, which includes the tags MPD does not index.

| Option                        | Default              | Meaning |
|-------------------------------+----------------------+---------|
| ~orpheus-lyrics-follow~       | ~t~                  | scroll to the line that is playing |
| ~orpheus-lyrics-buffer-name~  | ~"*orpheus lyrics*"~ | the buffer that shows them |
| ~orpheus-mpd-music-directory~ | ~nil~                | the local copy of MPD's library, for sidecar lyrics |

LRC times are followed; a file without times is shown as plain text.  A
positive ~[offset:+500]~ is subtracted from every time, as players do.  A
backend that cannot read lyrics answers nil, and the buffer says so instead of
staying empty.

| ~orpheus-vis-graphical~     | ~t~       | SVG bars in a graphical frame            |
| ~orpheus-vis-colors~        | five colours | the bar ramp, quiet to loud           |

On Windows, upstream cava rejects a configured input method; leave
~orpheus-vis-input~ nil so cava captures the default output.

~orpheus-theme-presets~ and ~orpheus-vis-theme-presets~ map a name to a plist
of colours, and ~orpheus-ui-layout-presets~ maps a name to a list of sections.
Add an entry and it joins the cycle: ~M-t~ walks the player themes, ~M-l~ the
layouts and ~M-c~ the visualizer ramps, while ~M-x orpheus-apply-theme~ and
~M-x orpheus-ui-apply-layout~ pick one by name.

* Complete examples

A daemon on this machine, with a shorter refresh and a larger cover:

#+begin_src emacs-lisp
(setq orpheus-backend 'mpd
      orpheus-mpd-socket "~/.mpd/socket"
      orpheus-refresh-interval 0.5
      orpheus-ui-art-size 260)
(orpheus)
#+end_src

A local library with a different look and a compact layout, and the equalizer
ready and the mode line showing the track:

#+begin_src emacs-lisp
(setq orpheus-backend 'local
      orpheus-local-directory "~/Music"
      orpheus-equalizer-enabled t
      orpheus-equalizer-preset "bass")
(orpheus-mode-line-mode 1)
#+end_src

Music copied from another machine, with three transfers in flight:

#+begin_src emacs-lisp
(setq orpheus-backend 'ssh
      orpheus-ssh-host "music.example.org"
      orpheus-ssh-directory "Music"
      orpheus-ssh-concurrency 3)
(orpheus)
#+end_src

In a graphical frame, the first line of the player shows the small orpheus logo
before the tabs.  There is no option to hide it; a terminal frame simply draws
the text without it.  The ~⧉ detach~ button at the end of that line, and
~M-x orpheus-detach~, move the player to a new graphical frame; the old window
is closed and the new frame is ordinary Emacs.
