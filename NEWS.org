* 0.2.1 (2026-11-07)

The 0.2.0 tag went up without a section of its own, so this one also carries
the changes since 0.1.0 that it already had.

*** Fixed

- `a' and `A' do nothing on the Queue tab.  Queuing a queue row appended the
  whole queue to itself, so one keystroke doubled it and a few of them filled
  the queue with copies of itself.  Every other tab still queues.
- `orpheus-version' said 0.1.0 while the file header had moved on, so the
  suite's consistency check failed on every run.
- An MPD that is not there is reported as a sentence that says where it looked
  and what went wrong — "cannot reach MPD at localhost:6600: Connection
  refused.  Is mpd running?" — instead of the raw `make-network-process' error.
  That error carried the arguments the process was made with, closures and all,
  so the message printed the connection, and the password inside it, into
  `*Messages*' on every attempt.
- The MPD password leaves the connection as soon as it has been sent, so a
  printed connection or a backtrace cannot repeat it.
- An MPD that answers and refuses — a wrong password, or none where one is
  required — is no longer reported as a daemon that is not answering.  MPD's
  own refusal is shown once, and the retry message says the daemon is there but
  refusing, which is the case a status read alone could not tell apart.

*** Changed

- The README says where the MPD password belongs: `~/.authinfo.gpg', read by
  `auth-source' through GPG, with `MPD_PASSWORD' kept for a single session.
  The recipe prompts for the secret instead of piping from `pass', which wrote
  a passwordless entry whenever `pass' was not installed.
- The README names the host and port the entry is looked up under, which are
  `orpheus-mpd-host' and `orpheus-mpd-port' even when the connection goes
  through a socket, and gives the GPG recipe in those two values instead of
  hardcoded ones.  It also says what a `pass' store needs: `auth-source-pass'
  switched on.
- The README says why the Queue tab can be full on the first start: MPD keeps
  the queue in its `state_file' and restores it, and orpheus adds nothing.

- 0.2.1, the release after 0.1.0.

* 0.1.0 (2026-11-07)

The first release.

*** Added

- =orpheus.el=, the player itself: the customization group, the backend
  selection, the status timer, the transport commands, the mode-line indicator,
  song-change notifications, and the entry points `orpheus',
  `orpheus-play-file', `orpheus-add-file' and `orpheus-play-url'.
- =orpheus-backend.el=, the protocol every backend implements: the
  `orpheus-track', `orpheus-status' and `orpheus-item' values, the registry
  behind `orpheus-register-backend', and the formatting helpers the interface
  draws with.
- =orpheus-mpd.el=, an MPD client written directly on `make-network-process':
  TCP and unix sockets, password from the environment or `auth-source',
  commands and replies serialized per connection, `ACK` errors handed to the
  caller, and the binary `albumart`/`readpicture` payloads written to the
  cache.  Status, current song, queue, directories, artists, album artists,
  albums, playlists, search, outputs, and the transport.
- =orpheus-local.el=, an mpv backend over the JSON IPC socket: a queue kept in
  Emacs, tags from mpv's `metadata`, cover art next to the file or extracted
  with ffmpeg, and URLs delegated to mpv (and so to yt-dlp).  The audio output
  follows the platform: PipeWire with PulseAudio and ALSA as fallbacks on
  Linux, CoreAudio on macOS, WASAPI on Windows.
- =orpheus-ui.el=, the interface: seven tabs in rmpc's order, a status line in
  the header line, a progress bar, cover art in a graphical frame, faces, the
  keymap modelled on Emacs and rmpc, mouse selection, and a help buffer.
- =orpheus-vis.el=, the visualizer: cava over PipeWire, PortAudio or WASAPI,
  read by a process filter and drawn as block characters in a terminal or as an
  SVG bar graph in a graphical frame.
- A unit suite that needs nothing but Emacs, including a fake MPD server on a
  loopback port, and an integration suite that plays through a real MPD and a
  real mpv and skips itself when the programs are missing.
- =maak.scm= with =compile=, =lint=, =test=, =integration=, =check=, =clean=,
  =repl= and the generated =AGENTS.md=.

*** Notes

- The local backend plays one file at a time, so consecutive tracks are not
  gapless; MPD's queue is gapless because the daemon owns it.
- The Windows named-pipe path in the local backend is written and compiled but
  has not been run.

*** Version

- 0.1.0, the first published version.
