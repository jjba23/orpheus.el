All notable changes to this project are documented in this file.  Changes are
listed per release, and within each release under additions, changes, fixes and
removals.

This project adheres loosely to [[https://semver.org/spec/v2.0.0.html][Semantic Versioning]].

* 0.17.0 (2026-11-10)

*** Added

- The equalizer remembers the curve in effect in
  ~orpheus-equalizer-state-file~: its gains, whether it is on, and the preset's
  name.  Every backend that starts, including the one a backend switch brings
  in, is given that curve, so a restart no longer begins flat.
- ~orpheus-equalizer-export-preset~ writes a preset to a file you name,
  ~orpheus-equalizer-import-preset~ reads a file holding one preset or many,
  and ~orpheus-equalizer-copy-preset~ puts one on the kill ring.  A file that
  holds a bare array of gains takes its own name.  The editor binds ~x~, ~I~
  and ~y~ to the same commands.
- The equalizer menu gains a Share group for the three commands.

*** Changed

- ~orpheus-equalizer--presets-text~ builds the JSON a preset file holds, so
  saving every preset and exporting one share the same shape.

*** Added

- ~E~ is the equalizer's simple mode.  The built-in presets now include night,
  podcast, acoustic, club and v-shape beside flat, bass, vocal, treble and
  loudness, and a saved preset is still one key away.
- ~M-E~ opens the equalizer's advanced mode: a bar graph of every band.  Up,
  down, left and right move the selected band, ~M-<up>~ and ~M-<down>~ move it
  farther, ~n~ and ~p~ change band, and a click inside a bar sets the gain of
  the column clicked.  ~0~ zeroes a band, ~r~ resets every band, ~i~ inverts
  the curve, ~t~ tilts it, and a right click opens the same commands as a
  menu.
- ~orpheus-equalizer-width~ sets the width of each band in octaves, and
  ~orpheus-equalizer-gain-step~, ~orpheus-equalizer-shift-step~ and
  ~orpheus-equalizer-tilt-step~ set how far one keystroke moves a band.
  ~orpheus-equalizer-set-width~ and ~orpheus-equalizer-set-max-gain~ change
  the two numbers the filter is built from without leaving the editor.
- ~L~ shows the lyrics of the current track in a side window and follows the
  playback, marking the line that is playing; RET on a line seeks to it and a
  click does the same.  LRC time tags, plain text and the offset tag are
  understood, and a line with several times yields each of them.
- Every backend answers ~orpheus-backend-lyrics~.  The local backend reads a
  ~.lrc~ or ~.txt~ file beside the track and then the lyrics tag inside it
  (ID3 USLT, Vorbis LYRICS, MP4 ©lyr, read with ~ffprobe~); SSH runs one
  quoted remote command for the sidecar names; MPD reads the sidecar under
  ~orpheus-mpd-music-directory~ or asks the daemon with ~readcomments~, which
  returns the tags MPD does not index.
- ~orpheus-lyrics-follow~ and ~orpheus-lyrics-buffer-name~ say whether the
  window follows the music and where it lives.

*** Changed

- The equalizer's line of ten gains is now a bar graph, and its filter width
  follows ~orpheus-equalizer-width~ instead of being fixed at one octave.
- The help buffer and the tutorial describe the two equalizer modes and the
  lyrics window.

* 0.15.2 (2026-11-10)

*** Added

- Any image file can be cover art, not only the names in
  ~orpheus-local-cover-names~.  Those names still win when several images are
  in the same folder, so ~cover.jpg~ beats a stray ~scan.jpg~, and
  ~orpheus-local-art-extensions~ says which extensions count.

*** Fixed

- The SSH cover search quotes the parentheses of its remote ~find~, so the
  remote shell no longer rejects the command with a syntax error.  A cover
  search that fails is also silent now: art is optional, and browsing the
  same folder reports a host that is really down.

* 0.15.0 (2026-11-10)

*** Added

- ~B~ and ~M-x orpheus-switch-backend~ switch to another registered backend
  without restarting Emacs.  The current backend is disconnected and the tabs
  are rebuilt for the new one.
- ~orpheus-ssh-control-directory~ chooses where ssh keeps its multiplexed
  control sockets, and ~orpheus-ssh-control-persist~ how long a shared
  connection stays alive after its last command.

*** Fixed

- SSH multiplexing no longer fails when the temporary directory is too long
  for a Unix-domain socket.  The control socket now lives in a short private
  directory under ~$XDG_RUNTIME_DIR~ or =/tmp=, and a host that still rejects
  it is retried once without multiplexing instead of failing the listing.

* 0.14.0 (2026-11-10)

*** Added

- Artwork is looked for in the track's folder, its parent (the album root
  above a disc folder) and one level of child folders such as =Scans/=.  The
  search runs in a separate process on the local backend and in one remote
  command on SSH, so a large folder or a slow link never blocks the interface.
- The now-playing card's controls follow the familiar media row: ~◁◁~, ~▶~ or
  ~⏸~, ~■~, ~▷▷~ and ~➦~ first, then ~⇆~, ~⤮~, ~①~, ~⊘~, search and help, as
  plain glyphs rather than boxes.  ~orpheus-ui-control-icons~ changes any of
  them.
- ~r~ cycles repeat through off, the queue and the current track; ~i~ prints
  the track, its tags and the position in the echo area; ~o~ opens the current
  file in the system's default program.
- SSH downloads live in ~orpheus-cache-directory~ (=~/.cache/orpheus/ssh= by
  default), survive a reboot, and are reused across sessions.
  ~orpheus-cache-max-bytes~ (10 GiB by default) bounds the whole cache by
  deleting the least recently used files; the track being played is never one
  of them.
- Six colour presets for the player — Aegean, Nord, Gruvbox, Rosé Pine,
  Solarized Light and Graphite — with ~orpheus-theme~, ~M-x
  orpheus-apply-theme~ and ~M-t~.  A preset recolours the faces and carries a
  matching visualizer ramp and background.
- Five named visualizer ramps (Aurora, Ember, Ice, Spectrum, Mono) with
  ~orpheus-vis-theme~, ~orpheus-vis-background~ and ~M-c~.
- ~orpheus-ui-layout~ lists the sections the player draws and in what order;
  ~orpheus-ui-layout-presets~ names classic, cover, compact and minimal, and
  ~M-l~ walks them.
- New faces ~orpheus-time-face~ and ~orpheus-help-key-face~, and
  ~orpheus-vis-status-face~ for the visualizer footer.
- ~orpheus-mpd-timeout~ drops a daemon that stops answering and reports the
  reason to every waiting caller; ~orpheus-ssh-command-timeout~ kills a
  listing, search or cover command that stays silent, so neither backend can
  hold a tab loading forever.  Downloads are never timed out.

*** Changed

- ~orpheus-ssh-cache-count~ is nil by default: the size limit decides, and the
  count is only a second, stricter limit for a small disk.
- The four modes show their state with the gold face on the same glyph, so the
  control row does not change width as they are toggled.

*** Fixed

- Changing folder while a download runs clears the old rows and shows
  ~loading…~ at once, so a slow answer is not mistaken for an ignored key.
  Listings, searches, size probes and covers share one multiplexed ssh
  connection (~orpheus-ssh-multiplex~), while downloads keep their own, so a
  saturated link no longer delays navigation.
- A lost MPD connection now answers the commands still in flight with the
  reason instead of leaving their callers waiting.
- The player drops a reply from an older, slower listing when a newer request
  has already started, and the test suite covers that race along with the SSH
  and MPD timeout paths.

* 0.10.0 (2026-11-09)

*** Added

- ~N~ creates a portable playlist: the player asks for a name and then for the
  directory to keep it in, starting in ~orpheus-playlist-new-directory~
  (=~/Music= by default), and opens it in the editor.  The Playlists tab reads

- ~?~ opens a transient menu over the transport, the four modes, the queue,
  playlists, the library and the views, each entry beside its key.  ~H~ keeps
  the full table, and the mouse context menus gain the menu and the new

  whole look is one ~customize-group~ away.
- ~maak demo~ records =screenshots/orpheus-demo.gif= reproducibly: a fixed

  ffmpeg assembles the frames.  It needs no player, daemon or network.

*** Changed

- ~orpheus-ui-open~ reuses the selected window, so opening the player no longer
  splits the frame.  ~orpheus-ui-display-action~ chooses another action.
- The now-playing card is drawn before the first track too, and its second line
  is always there, so the list does not jump when playback starts or a track
  gains an artist line.
- A tab loaded within ~orpheus-ui-cache-seconds~ is shown from memory; switching
  between a large queue and a directory no longer reads either again.  ~g~
  still forces a read.
- Decoded cover images are cached by file, size, modification time and scale,
  so a redraw every second does not decode the same cover again.
- SSH keeps ~32~ completed tracks in its cache instead of ~8~, enough for an
  album and the tracks the prefetcher has already fetched.

*** Fixed

- A redraw asked for while the buffer is being drawn is queued and run once
  after it instead of erasing the buffer a second time from inside a callback.
- The area kept for a cover that has not arrived is reserved in pixels, not in
  line heights.  A graphical frame used to put the list hundreds of lines
  below the cover, so opening the player scrolled the tabs, cover and card out
  of view.

* 0.8.0 (2026-11-08)

*** Added

- Portable playlists store library-relative paths when the queue names a file
  below the backend's library root.  ~local~ strips
  ~orpheus-local-directory~, SSH strips ~orpheus-ssh-directory~, and MPD strips
  the local music root; playback expands the relative path for the active
  backend.  A playlist saved from one backend can therefore play on another
  when the libraries mirror.  An absolute path outside the configured roots is
  still passed through unchanged.

*** Changed

- Playlist playback and append resolve relative URIs through the active
  backend instead of sending them to every backend unchanged.
- MPD's backend-level ~save~ and ~load~ actions remain for server-playlist
  compatibility; the player continues to save and open portable files.

* 0.7.0 (2026-11-08)

*** Added

- Cover art follows the current track and the album folder being browsed.  The
  local and SSH backends find ~cover.jpg~, ~Cover.PNG~, ~cover.webp~,
  ~folder.*~, ~front.*~, ~album.*~ and ~artwork.*~ case-insensitively; SSH
  copies a remote cover into the cache.  MPD uses its embedded art.  A track
  without art falls back to the folder being browsed.
- Art is centred using its actual pixel width, scaled to the window and
  ~orpheus-ui-art-size~, and an image Emacs cannot decode is skipped instead of
  breaking a redraw.  A terminal still fetches and draws nothing.
- Portable playlists: every backend now has a Playlists tab backed by M3U8
  files in ~orpheus-playlist-directory~.  ~C-x C-s~ saves the current queue
  from any backend, the tab reads existing M3U, M3U8 and PLS files, and RET,
  ~a~ and ~d~ play, append and delete them.  MPD's server playlists share the
  tab instead of disappearing.  Playlist URIs are passed to the active backend
  unchanged, so a playlist travels between backends only when its URI
  namespace does.
- The Playlists tab opens a portable playlist in an editor buffer with ~e~.
  ~M-<up>~ and ~M-<down>~ move a track, ~d~ removes it, and ~C-x C-s~ writes the
  M3U8 file back; parsed tags travel with the track.  PLS files stay read-only
  in the editor so a ~.pls~ name never receives M3U8 content.

*** Changed

- ~C-x C-s~ no longer sends MPD's server-side ~save~; it writes the queue as a
  portable M3U8 file, so a saved playlist is not tied to the backend that made
  it.  MPD's own playlists are still listed and playable in the Playlists tab.

* 0.6.0 (2026-11-08)

- When the remote shell cannot run ~cat~, SSH downloads fall back to ~sftp~.

* 0.5.1 (2026-11-08)

*** Fixed

- Remote search no longer fails when the host has no ~find~: it falls back to a
  recursive ~ls~, treats an empty result as no matches, and reports a complete
  failure only once instead of on every retry.
- SSH downloads no longer rely on ~stat~, ~wc~ or command substitution: the
  file streams with ~cat~, and a separate ~ls -lL~ probe supplies the size for
  progress when available.  A host that cannot report a size still downloads,
  showing ~--%~ and no ETA.

* 0.5.0 (2026-11-08)

*** Added

- SSH transfers have a visible Downloads tab.  Every request is a row, whether
  it is queued, downloading, finished or failed, with its byte count.  A
  running transfer also shows its completion percentage, rolling speed and
  ETA; RET plays a finished copy or retries a failure, and ~d~ cancels a
  transfer.
- SSH searches the remote library with ~find~ and the local backend searches
  below ~orpheus-local-directory~, both asynchronously and in the existing
  Search tab.  MPD search is unchanged.
- A now-playing card above the list shows the track, artist, album and a
  coloured progress bar.  ~orpheus-ui-show-now-playing~ turns it off.

*** Changed

- SSH downloads stream to a cache file as bytes arrive instead of collecting a
  whole track in an Emacs buffer and writing it from a sentinel.  Up to
  ~orpheus-ssh-concurrency~ transfers run at once, a play request goes ahead of
  background prefetches, the next ~orpheus-ssh-prefetch~ queue entries are
  fetched early, and the last ~orpheus-ssh-cache-count~ completed tracks stay
  cached.  The header line counts active and queued transfers and shows their
  aggregate throughput.

*** Fixed

- Starting a second SSH download while a track plays no longer freezes Emacs,
  and the previous track is no longer deleted on every new transfer.

* 0.4.0 (2026-11-08)

*** Fixed

- The ~../~ row now appears at a top-level directory and goes to the root, and
  RET on it moves the tab there instead of leaving only ~^~ to do the work.
- MPD refuses a directory URI, and ~A~ asks before queueing more than
  ~orpheus-ui-add-confirm-threshold~ tracks, so one keystroke cannot fill the
  queue with the whole library.  A queue over ~orpheus-ui-queue-warning-size~
  says so and names ~D~, which clears it.  Connecting itself queues nothing;

*** Changed

- The SSH backend no longer uses MPD.  It lists remote directories with ~ssh~,
  copies the selected track into a private temporary directory, and plays it
  with mpv, so the audio comes out of this machine and the far side needs no
  daemon.  The copy is removed on disconnect and when Emacs exits.
  ~orpheus-ssh-mpd-port~ and ~orpheus-ssh-local-port~ are gone;
  ~orpheus-ssh-directory~ sets where the files tab starts.
- ~p~ moves to the previous row, as it does in Dired.  ~SPC~ is the key that
  plays or pauses; ~RET~ still opens a directory or plays a row.
- The faces and the visualizer use a Greek palette: gold, marble, Aegean blue,
  iris and olive in either light, and a bar ramp from deep sea to gold.

* 0.3.0 (2026-11-08)

*** Added

- A clickable mode line: ~orpheus-mode-line-mode~ now shows the track even
  when nothing is playing, and the entry answers the mouse — left opens the
  player, middle plays or pauses, right opens a transport menu.  The width of
  the title is ~orpheus-mode-line-width~.
- The SSH backend, =orpheus-ssh.el=: a remote daemon reached through

  ~orpheus-ssh-mpd-port~, ~orpheus-ssh-local-port~, ~orpheus-ssh-program~ and

- ~u~ and ~U~ now unmark rows, as they do in Dired; updating and rescanning

  start back, and a terminal that cannot draw a picture extracts none.

  the same, instead of rebuilding the SVG for every timer tick.  A buried

* 0.2.1 (2026-11-07)

The 0.2.0 tag went up without a section of its own, so this one also carries
the changes since 0.1.0 that it already had.

*** Fixed

- ~a~ and ~A~ do nothing on the Queue tab.  Queuing a queue row appended the
  whole queue to itself, so one keystroke doubled it and a few of them filled
  the queue with copies of itself.  Every other tab still queues.
- ~orpheus-version~ said 0.1.0 while the file header had moved on, so the
  suite's consistency check failed on every run.
- An MPD that is not there is reported as a sentence that says where it looked
  and what went wrong — "cannot reach MPD at localhost:6600: Connection
  refused.  Is mpd running?" — instead of the raw ~make-network-process~ error.
  That error carried the arguments the process was made with, closures and all,
  so the message printed the connection, and the password inside it, into
  ~*Messages*~ on every attempt.
- The MPD password leaves the connection as soon as it has been sent, so a
  printed connection or a backtrace cannot repeat it.
- An MPD that answers and refuses — a wrong password, or none where one is
  required — is no longer reported as a daemon that is not answering.  MPD's
  own refusal is shown once, and the retry message says the daemon is there but
  refusing, which is the case a status read alone could not tell apart.

*** Changed

- The README says where the MPD password belongs: =~/.authinfo.gpg=, read by
  ~auth-source~ through GPG, with ~MPD_PASSWORD~ kept for a single session.
  The recipe prompts for the secret instead of piping from ~pass~, which wrote
  a passwordless entry whenever ~pass~ was not installed.
- The README names the host and port the entry is looked up under, which are
  ~orpheus-mpd-host~ and ~orpheus-mpd-port~ even when the connection goes
  through a socket, and gives the GPG recipe in those two values instead of
  hardcoded ones.  It also says what a ~pass~ store needs: ~auth-source-pass~
  switched on.
- The README says why the Queue tab can be full on the first start: MPD keeps
  the queue in its ~state_file~ and restores it, and orpheus adds nothing.

* 0.1.0 (2026-11-07)

The first release.

*** Added

- =orpheus.el=, the player itself: the customization group, the backend
  selection, the status timer, the transport commands, the mode-line indicator,
  song-change notifications, and the entry points ~orpheus~,
  ~orpheus-play-file~, ~orpheus-add-file~ and ~orpheus-play-url~.
- =orpheus-backend.el=, the protocol every backend implements: the
  ~orpheus-track~, ~orpheus-status~ and ~orpheus-item~ values, the registry
  behind ~orpheus-register-backend~, and the formatting helpers the interface
  draws with.
- =orpheus-mpd.el=, an MPD client written directly on ~make-network-process~:
  TCP and unix sockets, password from the environment or ~auth-source~,
  commands and replies serialized per connection, ~ACK~ errors handed to the
  caller, and the binary ~albumart~/~readpicture~ payloads written to the
  cache.  Status, current song, queue, directories, artists, album artists,
  albums, playlists, search, outputs, and the transport.
- =orpheus-local.el=, an mpv backend over the JSON IPC socket: a queue kept in
  Emacs, tags from mpv's ~metadata~, cover art next to the file or extracted
  with ffmpeg, and URLs delegated to mpv (and so to yt-dlp).  The audio output
  follows the platform: PipeWire with PulseAudio and ALSA as fallbacks on
  Linux, CoreAudio on macOS, WASAPI on Windows.
- =orpheus-ui.el=, the interface: seven tabs in the usual order, a status
  line in the header line, a progress bar, cover art in a graphical frame,
  faces, a keymap modelled on Emacs, mouse selection, and a help buffer.
- =orpheus-vis.el=, the visualizer: cava over PipeWire, PortAudio or WASAPI,
  read by a process filter and drawn as block characters in a terminal or as an
  SVG bar graph in a graphical frame.
- A unit suite that needs nothing but Emacs, including a fake MPD server on a
  loopback port, and an integration suite that plays through a real MPD and a
  real mpv and skips itself when the programs are missing.
- =maak.scm= with =compile=, =lint=, =test=, =integration=, =check=, =clean=,
  =repl= and the generated =AGENTS.md=.

*** Notes

- The Windows named-pipe path in the local backend is written and compiled but
